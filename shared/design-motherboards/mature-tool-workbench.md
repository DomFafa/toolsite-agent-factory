# Motherboard A — Mature Tool Workbench

## Purpose

Use this motherboard for serious, task-driven browser tools where users need speed, trust, clarity, and visible results.

Good fit:

- calculator
- checker
- converter
- counter / text analyzer
- file or image utility
- privacy/security utility
- typing/test/benchmark tool
- diagnostic or audit tool

## Visual feel

- Mature and credible.
- Clean light UI.
- Strong visual hierarchy.
- Medium density.
- Soft cards and refined spacing.
- Subtle geometric icon, line-art, or mini-diagram assets.
- Not cute, not dark, not dashboard-like.

## First viewport pattern

- Short title.
- Short subtitle.
- One to three trust/utility cues.
- Large workbench panel.
- Inside the workbench: left input/control area and right result/preview/feedback area.
- Result area changes by tool behavior:
  - calculator: big numeric result + assumptions/formula note
  - checker: score/pass-fail card + issue list
  - converter: source/target bridge
  - file tool: local preview + export/download affordance
  - tester: live score/progress + recent result cue

## Content modules

Choose modules by behavior, not by keyword root:

- file/format: How to use, format choices, privacy boundary, common problems, FAQ
- calculator: How to use, what the result means, formula/assumptions, examples, FAQ
- checker: How to use, what we check, how to fix failed results, best practices, FAQ
- counter/text: How to use, metrics explained, writing/editing use cases, FAQ
- tester: How to use, score meaning, practice tips, progress explanation, FAQ

## Asset language

- Primary: geometric icon, line art, mini diagram.
- Use one light scene illustration near the tool when it improves clarity.
- Each key section should have a small icon/doodle/visual marker.
- Assets must be standalone local files when selected.
- Do not embed text in image assets.

## GPT prompt block

Use Motherboard A as a design strategy. Create three distinct implementation-ready UI directions for this exact tool. Keep the page mature, credible, light, and tool-first. The first viewport must be a real usable tool. Use a short intro above a large workbench. Use left input/control and right result/preview/feedback in at least one direction, but vary the other directions through result emphasis, diagnostic layout, preview-first layout, or mobile ordering. Use subtle geometric icons, line art, or mini diagrams. Do not make the result generic. Do not create a SaaS marketing hero.
