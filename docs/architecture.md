# Architecture

## Purpose

Toolsite Agent Factory is a local, file-first agent system for repeatedly producing small, static, SEO-focused tool sites with distinctive UI and a reliable Cloudflare launch process.

## Non-goals for V1

- No full CLI.
- No visual dashboard.
- No backend service.
- No authentication.
- No database.
- No API-key workflow.
- No automatic production launch.
- No automatic cross-site related-tools graph.

## Main entities

### Agent

An agent is a task folder:

```txt
agents/agent-x-name/
  prompt.md
  input.schema.md
  output.schema.md
  checklist.md
  examples.md
```

Codex reads the folder, executes the task inside the local IDE, and writes outputs into a run folder.

### Run

A run is one local execution of the build pipeline for one site.

```txt
runs/<site-id>/
  input.md
  state.json
  approval.md
  agent-1-output/
  agent-2-output/
  agent-3-output/
  agent-4-output/
  agent-5-output/
  agent-6-output/
  site/
```

### Site

A site is an independent Astro project. It can be generated by copying `starter-site/` into `runs/<site-id>/site/` and then implementing the final tool.

## Pipeline overview

```txt
Agent 1: Keyword Research      independent, does not auto-trigger build
Agent 2: Site Brief            keyword + domain + requirements -> build brief
Agent 3: UI Code Prototype     code-first UI -> browser screenshots
Agent 4: Astro Implementation  implement site without redesigning UI
Agent 5: Strict QA             SEO, UI, mobile, build, behavior, index state
Agent 6: Launch                Cloudflare + DNS + analytics + indexing
```

## Deployment architecture

- Cloudflare Pages Direct Upload is the default launch path.
- Each site maps to one Cloudflare Pages project.
- Each Pages project maps to one independent domain.
- Production indexing is enabled only after QA passes and `approval.md` is completed.
